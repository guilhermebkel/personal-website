Giving an agent a read-only window into the Brazilian market

MCPFinance

An agent that can write SQL is only as useful as the table it is allowed to read. For better-investment-mcp I gave it one tool, query_sql, and a guide that explains the tables, instead of thirty tools that each answer one question.

Why one SELECT?

Every extra tool is another choice the agent has to make before it does anything useful. A single read-only query collapses that choice, and the guide does the teaching.

-- last dividends of a ticker SELECT paid_on, amount FROM dividends WHERE ticker = 'ITSA4' ORDER BY paid_on DESC LIMIT 5;
Figure 1. One tool, one guide, one read-only database.

What did the agent get wrong?

At first it joined everything. It answered quickly and confidently, and the numbers were wrong in ways that looked right. The fix was boring: shorter guide, named examples, and a note saying when a load is still running.

What would I do again?

Start with the smallest surface that works, then watch where the agent stumbles. The next change is almost always in the guide, not in the code.

SUMMARY
Prefer one well-explained, read-only tool over many narrow ones, and fix the guide before you fix the code.
